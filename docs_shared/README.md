# Shared docs

Outward-facing documentation for co-developers and users — how DevAnswers works and how to
use it. **Version-controlled** (committed to the repo), unlike `docs/` which is local-only
working notes.

Write for someone who didn't build the feature. Keep it accurate; update alongside the code.

Suggested contents (add as the project grows):
- `getting-started.md` — clone, install, env setup, run locally.
- `api.md` — REST endpoints, auth, request/response shapes.
- `features.md` — what the app does, from a user's point of view.
